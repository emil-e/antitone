# Pinned interactive ACES output shaders

Generated by OCIO **2.6.0** through `native/ocio_probe.cpp`, using `native/rendering_transform.h` and `scripts/probe-ocio.sh`. Current targets are **100-nit sRGB/D65 and P3/D65**, with AP1/D60 input. Rendering/limiting gamut matches each TIFF encoding gamut; Display P3 uses P3/D65 primaries with the sRGB transfer curve after rendering.

These are generated algorithms with two 363-entry 2D parameter tables per target, **not baked 3D LUT approximations**. `src/viewer.rs` adapts only resource declarations, combined-sampler glue and the fragment entry point. ACES mathematics are unchanged. Regenerate into ignored `.cache/probes/`, validate CPU/GPU agreement, then deliberately update these payloads when the native transform definition/version changes. Production does not generate shaders at startup.

ProPhoto was explicitly retired after yellow-to-gray boundary failures, including a similar failure in the proposed 100-nit SDR Rec.2020 target. The user approved P3 instead; it is not a silent narrower rendering in a ProPhoto container. Historical diagnoses: `../../docs/research/prophoto-gamut-diagnosis.md` and `../../docs/research/rec2020-rendering-gate.md`. Current evidence: [P3 output update](../../docs/research/p3-output-update.md).

Current CPU/GPU comparisons cover 4,816 pixels per target (including 3,072 camera-derived samples); maximum rendered-RGB error is `3.75509262e-6` sRGB / `2.86102295e-6` P3. Separate tests verify colored-grid preservation, yellow/exposure continuity and P3 colors outside sRGB. These checks are not full all-domain ACES conformance or physical-monitor matching.

LUT files contain little-endian f32, one channel for table 0 and three channels for table 1. The viewer expands texels to RGBA32Float without changing values and uses nonfiltering samplers.
