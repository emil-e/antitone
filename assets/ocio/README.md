# Pinned ACES output shaders

Generated by OCIO **2.6.0** through `native/ocio_probe.cpp`, using `native/rendering_transform.h` and `scripts/generate-ocio-reference.sh`. The separate `scripts/probe-ocio.sh` command regenerates these references and checks Metal agreement. Targets use AP1/D60 input and render to **100-nit sRGB or P3**, or **Rec.2020 at 500, 1000, 2000 or 4000 nits**, all with D65 white. Each payload is display-linear at 100 nits per unit.

These are generated algorithms with two 363-entry 2D parameter tables per target, **not baked 3D LUT approximations**. Preview and original-sample TIFF export share the [display rendering stage](../../src/photographic/stages/display_rendering.rs), which uses [a strict adapter](../../src/photographic/stages/display_rendering/aces.rs) to bind resources and translate the pinned GLSL into callable WGSL. The generated 363-value cusp hue array becomes an immutable read-only f32 buffer, initialized once per target from the unchanged literals; this avoids the measured Metal cost of its original constant-array layout. Unexpected declarations/counts or invalid values reject renderer initialization. Function bodies, table values and ACES mathematics are unchanged. Regenerate into ignored `.cache/probes/`, validate CPU/GPU agreement, then deliberately update these payloads when the native transform definition/version changes. Asset generation is offline; the stage adapts the pinned payloads when it initializes.

[Specialist checks](../../docs/diagnostics.md#rendering-gamut-and-icc) compare CPU/GPU rendering, coloured-grid preservation, yellow/exposure continuity and P3 colours outside sRGB. Numerical agreement is not full-domain ACES conformance or physical-monitor matching.

LUT files contain little-endian f32, one channel for table 0 and three channels for table 1. The display stage expands texels to RGBA32Float without changing values and uses nonfiltering samplers.

## Neutral exposure reference

`exposure-neutral-log2.f32` supports camera-preview brightness estimation without a runtime OCIO dependency. The same generator writes it into `.cache/probes/`: 257 little-endian f32 log2 scene-luminance values, sampled uniformly at display-luminance log2 values from −12 to 0. It inverts the neutral 100-nit sRGB ACES response before encoding; it does not invert a camera's creative rendering. Regenerate with `scripts/generate-ocio-reference.sh`, run the `exposure_reference` tests with `ocio-reference`, then copy the verified payload here. Its SHA-256 is `86253cbf2f979137282ce566a22184b3af7915f7bd747779293bd52a6cfbd2f5`.

## Fixed reference for creative-look generation

`authoring-reference.json` owns the p3rec50 D65/100-nit parameters. `authoring-reference/` pins its forward/inverse algorithms and reach/cusp tables with provenance for GPU conformance checks. The Spektrafilm exporter uses the inverse during offline component generation, independently of the selected output target. Regenerate these resources with `python3 scripts/spektrafilm/build.py reference --output .cache/authoring-reference-new`, using the normal pinned OCIO setup. [Component generation](../spektrafilm/README.md#regeneration) owns the dependency environment and promotion workflow.
