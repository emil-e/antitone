# Pinned ACES output shaders

Generated by OCIO **2.6.0** through `native/ocio_probe.cpp`, using `native/rendering_transform.h` and `scripts/generate-ocio-reference.sh`. The separate `scripts/probe-ocio.sh` command regenerates these references and checks Metal agreement. Current targets are **100-nit sRGB/D65 and P3/D65**, with AP1/D60 input. Rendering/limiting gamut matches each TIFF encoding gamut; Display P3 uses P3/D65 primaries with the sRGB transfer curve after rendering.

These are generated algorithms with two 363-entry 2D parameter tables per target, **not baked 3D LUT approximations**. Preview and original-sample TIFF export share `src/renderer.rs`, which uses [a strict resource adapter](../../src/renderer_aces.rs) for declarations, combined-sampler glue and the fragment entry point. The generated 363-value cusp hue array becomes an immutable read-only f32 buffer, initialized once per target from the unchanged literals; this avoids the measured Metal cost of its original constant-array layout. Unexpected declarations/counts or invalid values reject renderer initialization. Function bodies, table values and ACES mathematics are unchanged. Regenerate into ignored `.cache/probes/`, validate CPU/GPU agreement, then deliberately update these payloads when the native transform definition/version changes. Production does not generate shaders at startup.

[Specialist checks](../../docs/diagnostics.md#rendering-gamut-and-icc) compare CPU/GPU rendering, coloured-grid preservation, yellow/exposure continuity and P3 colours outside sRGB. Numerical agreement is not full-domain ACES conformance or physical-monitor matching. [Target rationale](../../docs/decisions/sdr-output-and-presentation.md).

LUT files contain little-endian f32, one channel for table 0 and three channels for table 1. The viewer expands texels to RGBA32Float without changing values and uses nonfiltering samplers.

## Fixed reference for creative-look generation

`looks-reference/` separately pins the p3rec50 D65/100-nit **forward and inverse** algorithms and their shared reach/cusp tables, with digests/parameters in `provenance.json`. They serve the native creative-look generator, not the selected output renderer. Its strict compute adapter retains the generated mathematical bodies; changing sRGB/P3 output does not change the creative look. Keep these generated resources outside the text-only material/source catalog. The [look guide](../looks/README.md#native-application-generation) owns generation, conformance fixtures and remaining approximation/acceptance limits.
