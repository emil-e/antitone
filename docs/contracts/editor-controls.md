# Editor control contract

Current UI/control behavior. Remaining work is scheduled in [the roadmap](../../PLAN.md), not in the verification snapshot below.

The editor uses `src/editor_controls.rs` and project-authored outline artwork in `src/editor_icons.rs` for a small shared hierarchy: **collapsible section → parameter row → specialized input**. `Editor::controls` owns roll/photo grouping and reset scope; the helpers own spacing, entry, range, focus and presentation. New grades use adjustable film response in native-camera model 4; old AP0 projects reject. Project schema/development identity are versioned accordingly; the output contract is unchanged.

## Layout and actions

- File (New, Open, Add RAWs, Save, Save As) and Export (TIFF, EXR half/full) menus replace action buttons within the existing header row; document name/Modified status stays single-line. No added toolbar row. Cmd-N/O/S and Cmd-Shift-S trigger file actions after accepted numeric/control edits; New/Open/Close share Save/Discard/Cancel protection.
- Full-width **Roll → Photo → Rendering** tabs precede one inspector scroll area, with equal hit regions and a selected underline. Arrows describe shared foundation → per-image work → rendered result, not operator execution order. **Scan orientation** and **Composition** belong to their respective tab's scroll area; neither geometry nor Output is pinned.
- **Composition** combines photo orientation and crop/straighten. It offers outline icons with action names/tooltips for Turn left/right, Flip horizontal/vertical, Crop and crop-only reset. During a crop draft the ordinary Composition actions remain visible/disabled with Crop highlighted. The section temporarily exposes its body, with an active-mode title/tint, aligned Aspect/preset/swap, Angle numeric/reset and Guides rows, and scoped draft reset in the mode heading. Ordinary expansion is restored on exit. Geometry Apply/Cancel live at the trailing edge of the fixed viewer bar on every inspector tab; other tabs may hide the settings without changing the draft/frame.
- Roll: **Scan orientation** (shared Turn left/right and Flip horizontal/vertical) → Flat-field correction → Calibration (RGB-only Dmin/Dmax) → Gamma & balance → Toe & shoulder → Exposure.
- Photo: **Composition** → White balance → Exposure. Orientation/framing is not repeated in a second Geometry section. Crop draft supports image-under-frame dragging, edge/corner resize and outside-frame straightening. Enter applies; Escape restores the initial framing/viewport. Rotated frames stay within actual source coverage. The marquee uses a thin contrasting border, corner brackets and short edge ticks, not filled object-resize handles. Thirds guides follow the crop and affect neither measurement nor export; denser alignment overlays remain deferred.
- Flip controls are momentary actions, never checked-state displays. Each flips the corresponding current displayed axis at its stage; applying it twice restores that stage. Quarter-turns still permute internal flip flags to turn the current composition correctly. Rotation/reflection order remains meaningful, but canonical flags are not exposed as a history of actions.
- Orientation is available with a loaded source even before calibration; actions/resets are disabled during picking/measuring and crop drafts. Accepted orientation edits Fit the new composition. Turn/flip controls retain the crop's selected source content. Roll turns/flips act on the shared scanning baseline before unchanged per-photo exceptions; photo actions transform what is currently displayed. Scan orientation reset and Composition reset are independent and preserve colour/calibration settings; Composition reset clears photo orientation/framing, while Reset crop clears crop/straightening and leaves exact orientation intact. Draft controls cannot change grading/output state or save/export half-applied framing.
- Rendering contains a collapsible **Target** section: labelled Display P3 / sRGB selector, scoped default reset and **Preview + TIFF · 100 nit** note. The shared target still affects preview, thumbnails, scopes and TIFF together; it is not the monitor profile, and AP0 EXR bypasses it. Its compact indicator remains in the fixed viewer bottom bar and scope caption. Target controls retain crop/flat-field draft guards.
- Each scalar row has its label/value/unit/reset above a full-width slider. Calibration rows share availability, RGB display and a pick action.
- Gamma balance and WB share a color component: wheel, warmth/tint rows and an eyedropper beside Neutral reference. WB owns a collapsible section; Gamma & balance has a flat Balance subgroup with its own reset, not a nested framed card. There is no separate “Neutral” reset button or hidden fitted baseline.
- Gamma & balance reset changes gamma/balance only; Toe & shoulder reset restores shared toe **2.5** / shoulder **0** without changing other edits; exposure resets affect their own scope only; color reset restores the actual zero-coordinate identity. Calibration is never erased by an edit-section reset. Gamma resets to **0.65**, not 1.
- A model-4 classic-curve diagnostic state shows “Classic curve · camera model 4” and an explicit **Use adjustable response** action. Drawing controls never opts in; the action preserves calibration/gamma/balance/exposure and changes only response. A reset does not convert an original grade.
- Shoulder **0 = off**. Both linked numeric/slider parameters share actual processing/fitting state; inverse poles and unsupported GPU range/precision are rejected atomically.
- Implementation details live in tooltips. Unsaved state, approximation/refinement and actionable errors remain visible. Successful refinement no longer overwrites an earlier pick/edit error in the status line.

## Shared visual language

Sections use a disclosure/title, optional trailing scoped reset and lightweight separators rather than nested card frames. Multiple sections may stay open. Expansion is stable per scope/section across tab and photo changes and application launches; changing it never dirties a project, changes processing or activates a hidden numeric edit. Adjusted sections stay collapsed with a non-default dot and concise **Adjusted** summary. Missing calibration remains visible in the collapsed summary; calibration has no generic reset.

Initial Roll expansion: Calibration and Gamma & balance open; Scan orientation, flat-field correction, Toe & shoulder and shared Exposure closed. Photo Composition, WB and Exposure start open. Rendering's Target starts open. Every successfully created New project selects Roll and opens missing Calibration, without expanding other adjusted sections; cancelled/failed New retains the tab. Open/import/photo switching otherwise retain tab semantics. Crop/flat-field drafts temporarily expose their existing Photo/Roll section bodies, without changing ordinary expansion preferences. Settings may disappear on another tab; viewer-bar Apply/Cancel and the draft/frame remain active.

Icons share project-authored 16-point outline artwork, 28-point pointer hit regions, meaningful widget names/tooltips, distinct disabled/hover/pressed/focus states and stable semantic IDs. Reset, eyedropper, turns/flips, crop, aspect swap and guides use these helpers; parameter names/values/units and Apply/Cancel remain text. Guides expose their actual toggle state; flips remain actions. Scope control rows reserve the same height in vector and waveform modes so icon hit targets do not shift the plot when switching modes.

Pressing a section disclosure while numeric text is pending cancels that pending edit rather than committing through focus loss; accepted values and precision are retained. Ordinary numeric Enter/focus-loss commits and Escape cancellation remain unchanged. Resets and disclosure do not trigger each other.

Section expansion, scope visibility/height ratio and filmstrip height are application preferences, not project fields. Normal launches load version-1 JSON at `~/Library/Application Support/Antitone/ui-preferences.json` on macOS; the host saves changed preferences atomically on event-loop exit, never on project Save. Missing files use defaults; malformed, unsupported-version or unreadable files are reported to stderr and left unchanged, using session defaults without a replacement write. Write failures are reported and do not affect project safety. Tab selection, scope plot/scale, inspection EV, viewport and tool drafts are not made durable. Tests/smokes use explicit defaults or temporary stores, never the user's preferences.

The fixed bottom viewer bar, shared active-tool group and inspector-owned geometry settings are implemented; the native menu bar remains **not wired**. [UI polish plan/checkpoint](../plans/ui-polish.md#slice-3-shared-tool-bar) owns delivery and visual-acceptance limits. Icon/disclosure accessibility metadata is tested headlessly; native VoiceOver delivery is not established by that test.

## Flat-field workflow

Choose reference RAW opens an uncorrected reference with a reference-specific automatic rectangular proposal, or manual selection if detection is ambiguous. Inspect/move/resize an integer rectangle in untransformed original-source coordinates using the shared canvas mapping; photo crop/straightening and roll/photo orientation are temporarily bypassed for this reference-support edit only. Apply correction accepts it and returns to the working photo; Cancel restores accepted composition and the exact original view/state. Estimation excludes borders before smoothing and rejects clipped/unusable support. The reference must be film-free and from the same scanning setup; metadata compatibility alone does not prove matching lighting/aperture/focus.

The Roll section shows filename, Enabled, Edit area and Clear before Calibration. New reference selection never adds a filmstrip photo or hides an existing one. Failed/stale/cancelled operations retain accepted map, grade and working context. Enabled/Clear preserve viewport and inspection mode. Dmin/Dmax are never resampled; the setup/calibration warning recommends re-picking after correction changes. Enabled/map/support are saved; reference-edit context and inspection EV remain transient. Active area editing exposes the existing Roll section with mode identity/progress; Apply/Cancel stay in the fixed viewer bar. No flat-field overlay obscures the support boundary.

## Numeric and keyboard behavior

| Parameter | Normal slider | Numeric/drag range | Default | Slider step / Shift step |
| --- | --- | --- | --- | --- |
| Gamma | 0.1…3 | 0.1…3 | 0.65 | 0.01 / 0.001 |
| Toe | 1…4 | 1…4 | 2.5 | 0.01 / 0.001 |
| Shoulder | 0…0.02 | 0…0.02 | 0 (off) | 0.0001 / 0.00001 |
| Exposure | −3…3 EV | −16…16 EV | 0 EV | 0.05 / 0.005 EV |
| Warmth / tint | −1…1 | −1…1 | 0 | 0.01 / 0.001 |

Numeric drag speed is 0.01 (shoulder: 0.0001), with egui's Shift-drag fine adjustment. Click or Tab to enter text; Enter/focus loss commits and Escape cancels. Model-range limits constrain numeric edits. Existing legal values are not rounded or clamped merely by drawing a row, including exposure outside the normal slider span. Moving the exposure track intentionally returns to its normal span. Display precision is separate from the stored f64 value.

Stable IDs separate roll, photo, sections and individual parameters. Disabled rows render a read-only value snapshot: egui 0.36.2's `DragValue` can otherwise commit pending text on focus loss **even while disabled**. Busy/overwrite transitions therefore cannot unexpectedly apply that text. Existing complete GPU-parameter validation still rejects unsupported combined proposals and restores the previous edits; there is no source-view or CPU fallback.

## Viewer navigation and source inspection

- Unmodified scroll pans both axes; Ctrl/Cmd-scroll or pinch zooms around the pointer. Multitouch uses its own center/translation and does not also apply synthetic wheel/zoom events.
- Fit uses the visible viewer canvas, excluding the inspector and a fixed 40-point viewer-width bottom bar above the filmstrip. Leading navigation/inspection/help use named outline icons; target/quality trail after flexible space. During every image tool, a trailing tinted group combines its icon/name, Cancel and primary Apply instead of target/quality; the unavailable source toggle is omitted. At constrained widths, zoom ± buttons and inline inspection EV yield to tool identity/actions; Fit, physical 100%, source inspection and help remain available. The displayed zoom percentage invokes physical-pixel 100%. Source mode alone shows the inspection control and **Source ±EV** (the inline value may yield at constrained widths, remaining in the control tooltip/popup); positive view hides both without resetting the value. Outside tool modes the bar retains target identity plus Approximate/Refining state, without a permanent ready row. Target identity remains in Rendering/scopes during tools. Viewer surround and bar share a darker surface, separated from the lighter filmstrip by its top divider. Loading, errors, source/positive view and tool entry do not change the canvas rectangle.
- Click a fitted image for physical-pixel 100% around that point; click an explicitly zoomed image to Fit. Zoomed primary drag pans; middle/Space-primary drag also pans during picking. `z` Fits unless text input has focus.
- Picker primary click/drag retains patch/rectangle priority; zoom, grabbing, crosshair, move and corner-resize cursors follow the active interaction. Picks remain in original developed-source coordinates through shared composition mapping; resize cursors follow canvas direction after orientation.
- Starting a picker retains zoom/pan and exact orientation. Gamma/WB keep the displayed grade/balance; Dmin/Dmax enter developed-source inspection, with working-photo viewport restoration after temporary reference selection. Dmin/Dmax temporarily reveal uncropped oriented source, preserving physical magnification and the original source-coordinate canvas-centre anchor. Picker UI never changes canvas size. The deliberate Dmin/Dmax domain change freezes a fitted view's physical scale/anchor; unchanged exit restores Fit, and Gamma/WB retain deliberate in-picker navigation. [Coordinate/view requirements](geometry.md#panels-and-picker-views).
- Crop entry Fits the full active source with a handle margin, not the accepted crop. Resizing and release retain source magnification/placement; angle changes retain magnification and the screen pivot. Explicit 100%, +/− and **Fit source** remain available. Only Apply Fits the finished composition; Cancel restores the pre-edit viewport. The provisional editing view does not request settled reconstruction, including when explicit zoom places the frame offscreen.
- While developed-source view is active, the **Source inspection** icon in the bottom bar opens a zero-default exposure adjustment with the standard exposure range/reset. It changes only source-preview brightness before unchanged ACES; it is not saved and does not affect RAW development, calibration, fitting, edits or exports. Positive preview ignores it. Positive viewing remains unavailable until Dmin/Dmax are measured; uncalibrated viewing stays source-only. Inspection/help popovers are keyboard-accessible and never resize the canvas.

## Contextual tools

Every image tool uses the same viewer-bar transaction group: recognizable icon, explicit mode name, Cancel then primary Apply, on one tinted surface at the trailing edge. The name is noninteractive mode identity, not a loose status message; accessibility identifies the active tool. While busy, a spinner replaces the icon and unsupported actions disable. Crop settings belong to Photo → Composition; flat-field editing stays in its existing Roll section. Dmin/Dmax/Gamma/WB have no separate tool panel. No tool overlay or placement chevron remains on the image. There is no generic Details, tool filename row or precise selection-coordinate entry. Gestures remain in viewer help and tooltips. Apply is present but disabled without a proposal; full-resolution measurement/flat-field acceptance disables unsupported actions, with no false cancellation.

Dmin/Dmax start on the current photo. To sample another image, select it in the filmstrip; only ordered roll sources are eligible, and Apply/Cancel returns to the original working photo, selection and precise view. There is no external calibration-reference chooser or unregistered calibration-sampling path. Flat-field's separate bare-light reference chooser/identity and accepted support workflow remain unchanged.

Only selection/frame artwork remains on the canvas. Inspector-owned crop aspect/angle/guides/reset remain the same cancellable draft; no implicit Apply on tab/outside clicks. Viewer-bar, inspector and popover pointer/drag/scroll gestures cannot also pick, resize, pan or zoom the canvas. Selection coverage remains visible while using tool controls.

Enter applies a valid proposal only when not consumed by numeric text or an open popover. Escape first cancels pending text/closes a specific popover, then exits the mode. Crop angle text commits on Enter/focus loss, not while typing; cancelled fields do not reconstruct/re-round geometry. Inline angle cancellation also rejects egui 0.36's delayed second lost-focus text commit. Numeric drag remains live. File/export/grade/target and reference-return guards are unchanged.

## Filmstrip thumbnails

The existing bottom strip shows approximate thumbnails of each accepted composition and filenames. Source/processed caches stay geometry-independent; crop/orientation/aspect are applied on paint. Selection is unavailable during a crop draft or flat-field support edit. Drag its top edge to change height (default 140 points, 52…240 points and window-height limited); images follow available height with preserved aspect. The preferred height persists as an application preference; window-height limits do not replace it, and the strip regains it when space returns. Scrolling and caches remain transient. None dirties/saves the project. A visible page fits the bounded cache; horizontally offscreen cells are virtualized.

Without calibration thumbnails show developed source at zero inspection gain; otherwise they show actual shared roll and each photo's grade through the existing GPU/ACES/managed presentation path. The viewer's source bypass/inspection EV does not change thumbnails. Enabled flat-field gains apply in original source coordinates; changing/clearing the map invalidates GPU image identity but reuses uncorrected RGB16 proxy cache entries. Normal selection and Dmin/Dmax reference-source selection retain their existing behavior. Loading placeholders and error markers/tooltips retain filenames and selection; thumbnails never supply measurements or export pixels.

## Image scopes

A distinct, shaded scopes region above Roll/Photo/Rendering switches waveform/vectorscope without changing viewer dimensions. Height follows sidebar width and a draggable bottom divider adjusts the scope/controls tradeoff; double-click resets sizing. Vectorscope is the initial plot, with labelled 1×/2×/4×/8× magnification and reset; intensity compensates for smaller chroma bins when magnified. Waveform has RGB/luma modes. RGB/CMY direction ticks/letters remain on the vector rim when zoomed, distinct from magnified 100% reference boxes. A dashed Skin hue guide is explicitly approximate, not a correctness test. Showing scopes reduces inspector scroll space while reserving its tab row and a usable scroll region. Visibility and height ratio persist as application preferences; plot/magnification remain session state. Both plots use the positive grade in the selected output's native encoded basis, labelled Whole frame / Approximate; source/reference/busy views and crop drafts suspend them. Accepted crop/orientation follows whole final-frame order, not viewer or source-bounding-box coverage. No project dirty/schema/export change. ## Resolve-style wheel orientation and mapping

Both wheels use the user's requested **blue at 3 o'clock, yellow at 9 o'clock**, with RGB/CMY proceeding clockwise. The displayed six sectors are equally spaced: R at 11, M at 1, B at 3, C at 5, G at 7, Y at 9. Artwork, labels, pointer input and marker positioning share the same orientation transform. This is a UI direction convention, not a claim about exact Resolve processing or the vectorscope's target-native luma/chroma measurement basis.

In a right/up plane, the existing opponent coordinates are projected with:

```text
P(rgb) = ((R-B)/sqrt(2), (R-2G+B)/sqrt(6))
O = [ -sqrt(3)/2   1/2       ]
    [  1/2        sqrt(3)/2  ]
```

- **Gamma balance:** display matrix `O`. Coordinates control relative log gamma in native-camera RGB, not RGB gains. Pixel response depends on the negative/calibration.
- **White balance:** display matrix `O * J`, where `J` is the exact differential AP1 neutral-white response to the existing Bradford log-cone-gain coordinates. With `C = Bradford * AP1_to_XYZ`, its columns are `P(C^-1 * diag(C*white) * opponent(1,0))` and the corresponding tint column. This is a local display adapter, not a replacement WB operator.

Each matrix is normalized by the maximum mapped corner length of the legal warmth/tint square. Input uses its inverse; coordinates outside the legal square are clipped to the existing ±1 limits. Wheel, sliders, numeric entry and fitted neutral corrections all share the same `Balance` state. There is no new saturation/strength state, physical Kelvin interpretation, or processing/profile change.
