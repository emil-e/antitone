# Editor control contract

Current UI/control behavior. Remaining work is scheduled in [the roadmap](../../PLAN.md).

The editor uses a small shared hierarchy: **section → parameter row → specialized input**. `src/editor_ui.rs` and its `editor_ui_hierarchy` submodule own presentation and UI-only hierarchy; `src/editor_controls.rs` supplies photographic parameter/calibration/balance adapters. `Editor::controls` owns roll/photo grouping and reset scope; numerical adapters retain entry, range, precision and disabled safety. New grades use adjustable film response in native-camera model 4; old AP0 projects reject. [Project state](project-state.md) and [output](output.md) define compatibility.

## Layout and actions

- File (New, Open, Add RAWs, Save, Save As) and Export (TIFF, EXR half/full) menus occupy the header row; document name/Modified status stays single-line. No added toolbar row. Cmd-N/O/S and Cmd-Shift-S trigger file actions after accepted numeric/control edits; New/Open/Close share Save/Discard/Cancel protection.
- Equal-hit-region **Roll → Photo → Rendering** stage tabs precede one tab-specific inspector scroll area. Roll is shared setup, Photo is per-image work, Rendering is the common preview/TIFF target; these are not independent processing pipelines. Successful accepted New selects Roll and opens missing Calibration; failed/cancelled/stale New and ordinary imports preserve tab/expansion.
- **Composition** on Photo combines turn/flip actions and crop/straighten. During cropping ordinary orientation actions stay visible/disabled, while a lightly tinted active-mode body exposes aligned Aspect/Angle/Guides rows and scoped draft reset. Roll/Rendering may hide settings without changing the draft, view or common viewer-bar Apply/Cancel. No orientation-in-draft behavior.
- Roll: **Scan orientation** → Flat-field correction → Roll analysis → Calibration (RGB-only Dmin/Dmax) → Gamma & balance → Toe & shoulder → White balance → Exposure.
- Photo: **Composition** → White balance → Exposure → Contrast → Saturation. Contrast owns amount/pivot and secondary Colour preservation (0 RGB log, 1 black-relative ratio proxy); Saturation owns amount and secondary Density (0 constant AP1 Y, 1 HSV-like maximum anchor). Both blends default to 0: ordinary RGB contrast and constant-luminance saturation. Colour preservation reduces contrast-driven colour changes but does not guarantee unchanged displayed saturation; Density is not a film-simulation control. Section resets affect only their own amount/pivot/blend, never WB/exposure/calibration. Orientation/framing is not repeated in a second Geometry section. Crop draft supports image-under-frame dragging, edge/corner resize and outside-frame straightening. Enter applies; Escape restores the initial framing/viewport. Rotated frames stay within actual source coverage. The marquee uses a thin contrasting border, corner brackets and short edge ticks, not filled object-resize handles. Thirds guides follow the crop and affect neither measurement nor export; denser alignment overlays remain deferred.
- Flip controls are momentary actions, never checked-state displays. Each flips the corresponding current displayed axis at its stage; applying it twice restores that stage. Quarter-turns still permute internal flip flags to turn the current composition correctly. Rotation/reflection order remains meaningful, but canonical flags are not exposed as a history of actions.
- Orientation is available with a loaded source even before calibration; actions/resets are disabled during picking/measuring and crop drafts. Accepted orientation edits Fit the new composition. Turn/flip controls retain the crop's selected source content. Roll turns/flips act on the shared scanning baseline before unchanged per-photo exceptions; photo actions transform what is currently displayed. Scan orientation reset and Composition reset are independent and preserve colour/calibration settings; Composition reset clears photo orientation/framing, while Reset crop clears crop/straightening and leaves exact orientation intact. Draft controls cannot change grading/output state or save/export half-applied framing.
- Rendering owns a scrollable **Target** section: Display P3/sRGB and scoped reset, labelled **Preview + TIFF · 100 nit**. It controls preview/thumbnails/scopes/TIFF, not the monitor profile or scene-linear AP0 EXR. Target changes/reset are disabled during crop and flat-field drafts. In-flight exports keep their original target/settings snapshot.
- Each scalar row has its label/value/unit/reset above a full-width slider. Calibration rows share availability, RGB display and a pick action.
- Gamma balance and WB use flattened section bodies: wheel, warmth/tint rows and neutral pick, with the section's scoped reset. There is no separate “Neutral” reset button or hidden fitted baseline.
- Gamma & balance reset changes gamma/balance only; Toe & shoulder reset restores shared toe **2.5** / shoulder **0** without changing other edits; exposure resets affect their own scope only; color reset restores the actual zero-coordinate identity. Calibration is never erased by an edit-section reset. Gamma resets to **0.65**, not 1.
- A model-4 classic-curve diagnostic state shows “Classic curve · camera model 4” and an explicit **Use adjustable response** action. Drawing controls never opts in; the action preserves calibration/gamma/balance/exposure and changes only response. A reset does not convert an original grade.
- Shoulder **0 = off**. Both linked numeric/slider parameters share actual processing/fitting state; inverse poles and unsupported GPU range/precision are rejected atomically.
- Implementation details live in tooltips. Unsaved state, approximation/refinement and actionable errors remain visible. Successful refinement must preserve a pending pick/edit error in the status line.

## Shared visual language

Recognizable actions use project-authored outline icons with semantic names/tooltips and distinct interaction/disabled states; tabs, parameter labels/values and Apply/Cancel retain text. Sections have independent disclosure/reset targets and accessible expanded state. Adjusted collapsed sections stay collapsed with a marker/summary; painting controls does not round values or alter reset scope. Roll Calibration/Gamma & balance/WB and Photo Composition/WB/Exposure/Contrast/Saturation start open; Analyze progress/actions remain visible without a disclosure; other setup sections start closed.

`editor_ui` provides shared control/viewer metrics, active-tool tint, text actions, labelled rows and tool-group presentation; its hierarchy submodule provides sections, stage tabs and symbolic expansion bookkeeping. Viewer zoom/Cancel/Apply, Analyze controls/confirmation, document/output confirmation actions and the inspector's explicit response opt-in use the same text-action presentation. Toolbar actions retain the 28-point minimum height (zoom also retains its 50-point minimum width); ordinary inspector text actions keep natural egui sizing/wrapping. Primary actions use the existing selection fill. Dynamic displayed labels can have a separate semantic name, as with zoom's **100%** action. Measuring single-line action widths neither allocates widgets nor changes IDs/focus; callers retain availability, help, layout and dispatch. Existing icon and numeric helpers remain specialized; native menus and specialized image visualization are not forced through text actions.

`ToolGroup` measures and draws the complete viewer identity/Cancel/Apply layout, including frame margins, from the same definition without allocating widgets during measurement. It returns the frame and both action responses; callers supply busy identity and action availability, choose placement/narrow-width priorities and dispatch transactions. `ToolIdentity::inspector` shares the icon/tint with the viewer but preserves the inspector's body-font title and all-around margins, rather than the viewer's 12-point title and horizontal margins. Inspector header actions and body contents remain caller-supplied; `controls::active_tool` retains crop draft reset semantics. Neither presentation adds ID scopes, keyboard handlers or implicit Apply/Cancel behavior.

`labelled_row` provides the existing 28-point row with a left label/optional help and right-aligned caller-supplied controls, returning the row and supplied results without an extra ID scope. Parameter and calibration adapters use it while retaining numeric fields, units, slider/RGB display, defaults and pick/reset behavior. `section` retains independent disclosure/reset, adjusted summaries and pending-numeric focus-loss protection; its expansion IDs and stage-tab hit regions remain unchanged. Flat-field text actions use natural `TextAction` sizing. Crop's aligned Aspect/Angle/Guides grid, balance artwork and scope chrome remain specialized.

`ContactSheetLayout` provides allocation-free normal/compact card sizing and pitch. `begin` paints the frame/well using the supplied ID and selected state, returning a `ContactSheetCard` with its interaction response and image bounds without consuming layout or auto-IDs. Callers paint image content, then use the card's loading/error/camera-badge and caption methods, preserving frame → well → image → badge/error → caption order. Card artwork derives hover/focus from its response; caption elision remains Unicode-safe and middle-biased toward the filename suffix. The filmstrip retains content/error precedence, image fitting and pixel-rounded GPU clipping/mapping, virtualization, tooltips, selection/availability and scheduling. Cards never own textures, documents, caches or workers.

The status bar's plain message, Analyze's measured sampling progress/indeterminate fitting row and canvas placeholders retain different presentation. Their text, phases and error priority belong to controllers; a generic notice wrapper does not introduce operation state or cancellation.

Symbolic section expansion, scope visibility/height ratio and preferred filmstrip height persist in version-1 application preferences, not project state. On macOS the file is `~/Library/Application Support/Antitone/ui-preferences.json`; other platforms use XDG config or `~/.config/antitone`. Load once; save changed preferences atomically after event-loop exit. Malformed/unreadable/unsupported files remain untouched with nonfatal diagnostics. Window constraints do not overwrite preferred sizing. Tabs, source EV, view, plots/magnification, drafts and resources remain transient.

## Flat-field workflow

Choose reference RAW opens an uncorrected reference with a reference-specific automatic rectangular proposal, or manual selection if detection is ambiguous. Inspect/move/resize an integer rectangle on canvas in untransformed original-source coordinates using the shared mapping; photo crop/straightening and roll/photo orientation are temporarily bypassed for this reference-support edit only. Apply correction accepts it and returns to the working photo; Cancel restores accepted composition and the exact original view/state. Estimation excludes borders before smoothing and rejects clipped/unusable support. The reference must be film-free and from the same scanning setup; metadata compatibility alone does not prove matching lighting/aperture/focus.

The Roll section shows filename, Enabled, Edit area and Clear before Calibration. New reference selection never adds a filmstrip photo or hides an existing one. Failed/stale/cancelled operations retain accepted map, grade and working context. Enabled/Clear preserve viewport and inspection mode. Dmin/Dmax are never resampled; the setup/calibration warning recommends re-picking after correction changes. Enabled/map/support are saved; reference-edit context and inspection EV remain transient. Active area identity/progress lives in the existing Roll section; Apply/Cancel use the shared viewer-bar group, not an extra panel.

## Analyze roll

**Analyze roll** is one explicit grade reinitialization action: eligible film sampling → Dmin → independent-channel Dmax tails → WB-independent shared channel-curve fit → shared photographic roll WB → individual total exposures. It replaces calibration/channel balance, roll WB/EV and every ordered Photo's EV/WB, including authored 0 EV; zero is not an unset marker. Photo WB resets to zero for manual local/creative adjustment, not individual gray-world fitting. All Photo creative controls reset to defaults: contrast 1, pivot 0.18, colour preservation 0, saturation 1 and density 0.

If any ordered Photo settings differ from the complete defaults, a pre-analysis confirmation warns that existing Photo adjustments will be replaced, with **Cancel / Analyze roll** and reassurance that crop, orientation and correction are preserved. Fresh/default Photos analyze directly without reset-warning text. This comparison adds no authored/untouched tracking. Pending numeric edits are processed before checking/snapshotting; modal cancellation changes no processing state. Changed/stale dialog context cannot authorize a different roll or grade. Selected global gamma/response, correction, accepted statistics area, roll/photo orientation and crop/straightening are preserved. Ordinary manual edits, picks and picture-area changes never trigger re-analysis or exposure/WB placement.

The robust exposure prior blends p99-capped positive mean→0.18 and p99→1 equally in EV, evaluated after gamma and roll WB. Roll EV is the median desired total; Photo EV stores each residual, so common correction does not consume the Photo control's useful range. This is one calculated appearance, not a second normalization. Roll WB and Photo WB have separate persistent controls, expansion and resets; the Photo neutral picker measures a replacement residual after roll WB, while the Roll neutral picker measures the shared replacement without Photo WB.

The backend snapshots the document, ordered source IDs, fixed WB, camera basis and accepted correction. Loadability/development compatibility is checked without RAW content hashing. Bounded original-pixel samples are checked for capture/development clipping and effective floor; these checks do not identify film material. Adequacy requires at least 512 picture samples per frame, 2,048 pooled film samples, 256 positive balance samples per frame and 512 positive exposure samples per frame. A frame may contribute no film base. The complete proposal, every Photo's GPU constants and correction domains validate before one atomic installation, with no additional proposal approval. Progress and **Cancel analysis** use a dedicated generation; failure/cancellation/stale replies preserve settings and an unchanged settled preview. Pending refinement is cancelled without discarding accepted settled pixels; successful installation invalidates the old grade's rendering. Native calls and submitted GPU work are not interruptible mid-phase.

**Edit picture area…** temporarily shows uncropped, untransformed developed source. Its editable integer source rectangle affects Dmax/balance/exposure statistics, not output crop/straightening or Dmin picker context. Accept/Cancel restores the working composition/view; acceptance changes geometry only. Analysis and area actions are unavailable during a crop draft. Film sampling separately includes suitable margins/interior inside shared support. Accepted correction support takes precedence as the suggestion; otherwise Analyze searches compatible roll sources for an illumination opening. No opening and no explicit area fails unchanged with an actionable edit-area message—picture statistics never silently fall back to the entire camera image. Sources without a local hint may use shared support. Explicit accepted geometry wins; **Reset picture area** discards it and cached hints without changing the grade, so the next Analyze seeks a new suggestion.

These are scene-dependent initialization heuristics, not physical Dmin/Dmax or calibrated colour truth. The opening suggestion is editable, not reliable segmentation. Use the ordinary Dmin picker/manual adjustments afterwards; photographic acceptance remains open. [Numerical estimator](processing-model.md#camera-source-representation), [persistence](project-state.md#picture-analysis-area).

## Numeric and keyboard behavior

| Parameter | Normal slider | Numeric/drag range | Default | Slider step / Shift step |
| --- | --- | --- | --- | --- |
| Gamma | 0.1…3 | 0.1…3 | 0.65 | 0.01 / 0.001 |
| Toe | 1…4 | 1…4 | 2.5 | 0.01 / 0.001 |
| Shoulder | 0…0.02 | 0…0.02 | 0 (off) | 0.0001 / 0.00001 |
| Exposure | −3…3 EV | −16…16 EV | 0 EV | 0.05 / 0.005 EV |
| Warmth / tint | −1…1 | −1…1 | 0 | 0.01 / 0.001 |
| Contrast | 0.4…1.6 | 0.4…1.6 | 1 | 0.01 / 0.001 |
| Pivot | 0.01…1, logarithmic track | 0.01…1 linear AP1 | 0.18 | 0.001 / 0.0001 |
| Colour preservation / Density | 0…1 | 0…1 | 0 | 0.01 / 0.001 |
| Saturation | 0…2 | 0…2 | 1 | 0.01 / 0.001 |

Numeric drag speed is 0.01 (shoulder: 0.0001), with egui's Shift-drag fine adjustment. Click or Tab to enter text; Enter/focus loss commits and Escape cancels. A stage switch processes outgoing numeric controls before changing the inspector body, so accepted pending text is not lost before Analyze. Model-range limits constrain numeric edits. Existing legal values are not rounded or clamped merely by drawing a row, including exposure outside the normal slider span. Moving the exposure track intentionally returns to its normal span. Display precision is separate from the stored f64 value.

Stable IDs separate roll, photo, sections and individual parameters. Disabled rows render a read-only value snapshot: egui 0.36.2's `DragValue` can otherwise commit pending text on focus loss **even while disabled**. Busy/overwrite transitions therefore cannot unexpectedly apply that text. Existing complete GPU-parameter validation still rejects unsupported combined proposals and restores the previous edits; there is no source-view or CPU fallback.

## Viewer navigation and source inspection

- Unmodified scroll pans both axes; Ctrl/Cmd-scroll or pinch zooms around the pointer. Multitouch uses its own center/translation and does not also apply synthetic wheel/zoom events.
- One fixed 40-point viewer-width bar keeps canvas dimensions stable across tool transitions. Fit/physical-pixel 100%/zoom, source view, source-only inspection and help lead; target/Approximate/Refining/Cached preview state trails outside tools. No permanent ready row or tool filename/coordinate panel.
- Click a fitted image for physical-pixel 100% around that point; click an explicitly zoomed image to Fit. Zoomed primary drag pans with a Grab hover cursor when panning is possible and Grabbing during the drag; click-to-Fit remains available. Middle/Space-primary drag also pans during picking. `z` Fits unless text input has focus.
- Picker primary click/drag retains patch/rectangle priority; zoom, grabbing, crosshair, move and corner-resize cursors follow the active interaction. Picks remain in original developed-source coordinates through shared composition mapping; resize cursors follow canvas direction after orientation.
- Starting a picker retains zoom/pan and exact orientation. Gamma/WB keep the displayed grade/balance; Dmin/Dmax enter developed-source inspection, with working-photo viewport restoration after temporary roll-source selection. Calibration sampling uses only ordered filmstrip sources; no external/unregistered chooser. Dmin/Dmax temporarily reveal uncropped oriented source, preserving physical magnification and the source-coordinate canvas-centre anchor. Unchanged exit restores Fit; Gamma/WB retain deliberate in-picker navigation. [Coordinate/view requirements](geometry.md#panels-and-picker-views).
- Crop entry Fits the full active source with a handle margin, not the accepted crop. Resizing and release retain source magnification/placement; angle changes retain magnification and the screen pivot. Explicit 100%, +/− and **Fit source** remain available. Only Apply Fits the finished composition; Cancel restores the pre-edit viewport. The provisional editing view does not request settled reconstruction, including when explicit zoom places the frame offscreen.
- Every image tool uses one trailing tinted viewer-bar group: recognizable icon/name, Cancel then primary Apply. The name→Cancel gap is 12 points; buttons remain closely grouped. Busy work replaces the icon with a spinner and disables unsupported actions; Apply remains present/disabled without a proposal. Target/quality and the unavailable source toggle yield to the group. At narrow widths auxiliary zoom ± and inline EV yield first; Fit/100%, inspection and help remain. Only selection/frame artwork stays on canvas; no floating box, generic Details or placement chevron.
- Enter/Escape and existing Apply/Cancel transaction boundaries remain; numeric entry/popovers own keys first. Bar/inspector/popover gestures cannot also manipulate the canvas. Tab changes/outside clicks never implicitly accept/discard a draft.
- Source-only **Inspection** opens a zero-default exposure adjustment with the standard range/reset. Hidden inspection retains EV. It changes only source-preview brightness before unchanged ACES; it is not saved and does not affect development, calibration, fitting, edits or exports. Positive preview ignores it.

Normal registered-photo switches can show **Cached preview · developing full-resolution RAW…** from a compatible retained 256 RGB16 proxy. It follows the selected photo's current grade, target and accepted composition, with separate source-inspection brightness. It is display-only: picks, crop edits, refinement, scopes and exports stay unavailable until full preparation completes. Memory misses/stale keys keep the loading placeholder; failure/replacement removes cached display. Temporary picker/reference loading does not adopt it. Preview admission does not change saved state.

## Filmstrip thumbnails

The bottom strip shows approximate thumbnails of each accepted composition in equally sized, neutral dark cards. Images fit whole within inset square-cornered wells; portrait and unusual-aspect compositions remain centred, not cropped. A thin accent outline and restrained neutral lift identify the selected card; hover is a quieter neutral outline/lift with no geometry change. Filenames are centred on one line, with middle ellipsis prioritizing the trailing frame identifier and extension when space is limited; tooltips retain full paths/error information. Compact strips reduce inset/caption spacing and keep an 80-point minimum card width. Source/processed caches stay geometry-independent; crop/orientation/aspect are applied on paint. Selection is unavailable during a crop draft or flat-field support edit; a crop draft also suspends new thumbnail scheduling. Drag its top edge to change height (default 140 points, 52…240 points and window-height limited); images follow available height with preserved aspect. Partial images at scroll edges are cropped, not squeezed; their callback bounds and composition mappings follow the visible, pixel-rounded portion. Resizing, scrolling and caches are transient and do not dirty/save the project. Horizontally offscreen cells are virtualized; cache capacity does not dictate cell width. Visible entries are protected from eviction and missing visible cells do not wait for settled refinement or grading idle after foreground preparation. Worker completion requests immediate repaint. Recent entries support scrolling back, and normal-pressure idle prefetch for nearby and then unshown photos is lower priority and uses only spare retention budget. Optional retention scales with machine capacity and memory pressure; [cache contract](output.md#responsiveness-and-optional-caches).

Without calibration thumbnails show developed source at zero inspection gain; otherwise they show actual shared roll and each photo's grade through the existing GPU/ACES/managed presentation path. The viewer's source bypass/inspection EV does not change thumbnails. Enabled flat-field gains apply in original source coordinates; changing/clearing the map invalidates GPU image identity but reuses uncorrected RGB16 proxy cache entries. Normal selection and ordered-roll Dmin/Dmax sampling preserve working-photo return state. Missing visible developed thumbnails can temporarily show a labelled **Camera preview**: a small, display-referred embedded JPEG with the camera's full framing/orientation, not the accepted RAW crop, inversion, grade, correction or source-inspection gain. Uncalibrated generated thumbnails also show source; saved calibration applies only when the proper developed thumbnail replaces the camera preview. Camera-preview images and badges stay within the inset well and its scroll clip; compact wells shorten the badge to **Camera** without replacing the filename. Camera previews use managed egui sRGB presentation and remain filmstrip-only: they never become a selected pending preview, `Ready`/`Scan`, picker/scopes or export input. Missing/unsupported/bad JPEGs keep the loading placeholder; authoritative RAW errors take precedence. Thumbnail loading/error states retain filenames and the working-photo selection while `Ready` or a pending selected preview exists. Cold loading/failed selected-source preparation without either currently loses the selected outline; this is a known [interaction follow-up](../plans/inspection-and-interaction.md#focused-fixes). Thumbnails never supply measurements or export pixels. Verified selected development seeds a thumbnail instead of being developed again. Grade/view edits reuse source work, obsolete scroll jobs cancel between phases, and a disposable persistent RGB16 cache avoids re-development on later visits/restarts. Critical memory pressure suspends new thumbnail work without changing the grade or hiding existing visible images.

## Image scopes

A separate shaded inspection region above Roll/Photo/Rendering switches waveform/vectorscope without changing viewer dimensions. Height follows sidebar width and a draggable bottom divider adjusts the scope/controls tradeoff; double-click resets sizing. Vectorscope is the initial plot, with labelled 1×/2×/4×/8× magnification and reset; intensity compensates for smaller chroma bins when magnified. Waveform has RGB/luma modes. RGB/CMY direction ticks/letters remain on the vector rim when zoomed, distinct from magnified 100% reference boxes. A dashed Skin hue guide is explicitly approximate, not a correctness test. Showing scopes reduces inspector scroll space while retaining stage tabs; visibility and size are application preferences, and Target stays in Rendering. Both plots use the positive grade in the selected output's native encoded basis, labelled Whole frame / Approximate; source/reference/busy views and crop drafts suspend them. Accepted crop/orientation follows whole final-frame order, not viewer or source-bounding-box coverage. No project dirty/schema/export change. ## Resolve-style wheel orientation and mapping

Both wheels use **blue at 3 o'clock, yellow at 9 o'clock**, with RGB/CMY proceeding clockwise. The displayed six sectors are equally spaced: R at 11, M at 1, B at 3, C at 5, G at 7, Y at 9. Artwork, labels, pointer input and marker positioning share the same orientation transform. This is a UI direction convention, not a claim about exact Resolve processing or the vectorscope's target-native luma/chroma measurement basis.

In a right/up plane, the existing opponent coordinates are projected with:

```text
P(rgb) = ((R-B)/sqrt(2), (R-2G+B)/sqrt(6))
O = [ -sqrt(3)/2   1/2       ]
    [  1/2        sqrt(3)/2  ]
```

- **Gamma balance:** display matrix `O`. Coordinates control relative log gamma in native-camera RGB, not RGB gains. Pixel response depends on the negative/calibration.
- **White balance:** display matrix `O * J`, where `J` is the exact differential AP1 neutral-white response to the existing Bradford log-cone-gain coordinates. With `C = Bradford * AP1_to_XYZ`, its columns are `P(C^-1 * diag(C*white) * opponent(1,0))` and the corresponding tint column. This is a local display adapter, not a replacement WB operator.

Each matrix is normalized by the maximum mapped corner length of the legal warmth/tint square. Input uses its inverse; coordinates outside the legal square are clipped to the existing ±1 limits. Wheel, sliders, numeric entry and fitted neutral corrections all share the same `Balance` state. There is no new saturation/strength state, physical Kelvin interpretation, or processing/profile change.

## Verification

Cards currently lack accessible filename/selection metadata; pinned section titles lack label semantics, and wheels have no named keyboard interface beyond the adjacent warmth/tint controls. Rejected filmstrip selection actions still expose enabled card responses. These known [selection/accessibility gaps](../plans/inspection-and-interaction.md#focused-fixes) remain separate from physical/VoiceOver acceptance; equivalence tests preserve existing semantics rather than establish complete accessibility.

Headless event/layout checks cover numeric precision and range, keyboard/mouse entry, Enter/Escape, pending-edit disable transitions, wheel mapping and disabled behavior, true scoped defaults/resets, section order and control reachability at normal/narrow widths. Wheel adapters are checked independently for full-square round-trips, local WB response and blue/yellow orientation.

[Specialist verification](../build-and-probes.md#editor-and-layout-smoke) provides real-image layout commands with diagnostic settings. Headless events and scripted visible frames do not establish physical trackpad feel, photographic correctness or device/monitor acceptance.
