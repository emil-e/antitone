# Export performance follow-up

Production export uses authoritative original-sample GPU processing, exact f64 reconstruction and CPU encoders. Straightened compositions reuse completed tiles within one immutable job; the [output guide](../colour-and-output.md#tiff-and-exr-serve-different-purposes) owns that contract. Matched scalar/OCIO-reference measurements and bounded cache comparisons are available through the [full-size diagnostic](../diagnostics.md#export).

Bounded reuse, exact clipping/locality, range-reduced compensated GPU math, overlapped TIFF geometry planning, two-original rendered-output batches and bounded future-use retention reduce measured stage costs, but do not establish isolated hardware throughput, a minimum chip/RAM target or universal latency. The reference adapter is an independent measurement oracle, not a production renderer. [Bounded reuse observations](../diagnostics.md#bounded-reuse-observations) record the measured results and their power/workload limits.

## Remaining scope and acceptance

- Establish realistic latency/throughput expectations using matched hardware, source resolution, cold versus already-developed inputs, output format/compression, correction and straightening. Compare single-image latency separately from batch throughput; document prior-art measurement conditions rather than inventing a Lightroom baseline. Broaden characterization across source sizes, crop alignment, exact turns, both targets and output precisions. Include ordered locals and signed/HDR/floor/bypass cases in correctness checks and use a coordinated timing window with logged power source/mode before attributing small differences.
- Investigate output-specific representation separately from photographic arithmetic. Lossless f32 storage of already-rendered TIFF cache values demonstrated smaller tile payload, but no latency win on the measured traversal; it is not a selected performance default. The current EXR path retains compensated AP1 through reconstruction; the numerical checks measure its agreement with the original-sample reference. Any lower-precision arithmetic or future 8-bit path needs explicit final-output error bounds across the supported domain, not an assumption that final quantization makes earlier errors harmless.
- Use stage breakdowns before selecting algorithms or scheduling. Broaden balanced full-file/resource comparisons when preflight permits; exact CPU planning may become exposed as GPU consumption shortens.
- Characterize bounded forecast reuse across more geometry/source/device cases before expanding retention or concurrency. Separate reductions in original evaluations from launch-count changes. Log power state, compare both run orders and preserve unfavorable/noisy observations.
- Cross-plan pairing of already-required misses may reduce the many remaining single-original launches, but is not implemented. With the existing pipeline, a pending second value interacts with permits, the two-plan rendezvous and source/cache bounds. Changing those lifetimes or adding speculation or another GPU submitter would change resource and scheduling behavior, not merely reduce launches. A theoretical launch floor is not a measured speedup. GPU processing-pass elapsed can include scheduling/memory stalls; unsupported or stale render-end queries do not establish isolated ACES/copy costs.
- Evaluate lossless TIFF storage independently of processing: fast Deflate reduced measured encoding time and file size, while uncompressed output traded larger files for lower encoding cost. Both preserved tested RGB16/profile data, but neither is a selected default. Replacing LZW would change the file-format choice; the measured encoding benefit does not establish broader source/reader compatibility.
- More retained tile payload can reduce repeated GPU work, but capacity and traversal interact; choose any larger budget explicitly from measured benefit and memory/lifetime cost, not by silently increasing normal limits.
- Keep additional ownership explicit: completed geometry plans, construction/stack transients, completed CPU tile payload, current upload/readback, encoded frame, retained working detail/underlay and encoded/in-flight/native-retired resources. A bounded job cache is not a full-source float store or an aggregate admission guarantee. Measure benefit and lifetime before expanding it.
- Correctness checks cover original processing, exact geometry, supplied-sample encoding, profiles/metadata, immutable snapshots and destination safety. Export still derives from originals rather than previews, with compensated AP1 retained through EXR reconstruction. A change in precision, clipping or supported domain is a change in output behavior, not a behavior-preserving scheduling optimization.
- Repeat bounded resource observations with unchanged pressure, swap-counter, growth, duration and unavailable/stale-telemetry stops. Footprint, resident memory and Metal allocation overlap and must not be added. Do not improve a result by increasing normal cache limits or relaxing diagnostic allowances.

The [development checks](../development.md#export-checks) provide the normal verification route. Software agreement is not photographic or physical-display acceptance. Forced-pressure exercises, native application automation and system setup still require separate authorization. This plan records follow-up scope, not authorization to start it.
