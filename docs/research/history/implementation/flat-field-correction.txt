Correct lens/light-source spatial exposure variation using a separate unclipped RAW of the same scanning setup without film. The user selected this work after the editor commit and approved **rectangles only**, with automatic detection where simple and an editable result. No holder-specific geometry, polygons, ML segmentation, dust-removal feature, changed RAW development or ACES changes.

The correction is a smooth **three-channel source gain field**, correcting brightness and spatial colour shading and **neutralizing the reference to uniform gray**. Set neutral target luminance from an averaged image-centre area: centre brightness is preserved, but centre colour need not be and the three centre gains need not equal one. Estimate it only from the valid illuminated rectangle: rig borders must never enter smoothing/estimation. This is distinct from Dmin/Dmax and from transient source-inspection brightness.

Read-only photographic inputs: `samples/DSC01739.ARW` and `samples/DSC01813.ARW`; corresponding negatives precede them. **Do not use `DSC01738.ARW` or `DSC01812.ARW`**, which the user considers overexposed. These references represent one setup only, not a template for other holders.

## Design and questions to settle from evidence

- The user clarified the earlier exposure-only description: **three gains at every point and a neutral-gray target**, not preservation of the reference's central tint. Define neutral gray in the working colour convention, not by blindly equating sensor channels. Derive the corresponding camera-RGB target using the source matrix; apply gains to linear developed camera RGB before camera-to-AP0 conversion/inversion. High CRI is assumed, but does not prove spatial colour uniformity or exact spectroradiometric correction.
- Automatically propose an axis-aligned illuminated rectangle from linear reference data around the central light-source region. Keep manual edge adjustment and explicit acceptance. Dust must not turn into mask holes. Ambiguous detection must not become an assumed full-frame mask.
- Downsample through block statistics, not sparse viewer samples. Boundary-containing blocks must be excluded before field estimation. Compare robust smooth-surface fitting with masked filtering: excluding dark borders alone does not remove the slope bias of a truncated blur kernel at the boundary.
- Evaluate source-coordinate centre samples and the correction consistently on CPU/GPU. A small smooth field should suffice, but choose resolution/filter scale from measured reconstruction error, not a guessed hardware budget.
- Correction enters before camera-to-AP0 conversion/inversion, on full-resolution source coordinates, preserving signed/HDR values in temporaries and retained RGB16. Apply consistently to source view, picks/fitting, interactive/settled previews, thumbnails and TIFF/AP0 EXR.
- Settle corrected precision-floor/range validation, including gains below one and shader temporary precision. No new clamp, pedestal, CPU viewer fallback or weakened tolerance.
- Define behavior outside the accepted rectangle without inventing measurements or unbounded extrapolation. The valid rectangle describes support for estimation/correction, not an implicit photo crop.
- Persist accepted map/settings and reference identity with explicit compatibility; uncorrected existing projects/grades retain their behavior. Dmin/Dmax stay RGB-only: adding/replacing a field never silently resamples them. Explain calibration order/re-picking when enabling correction on an existing grade.
- Approved UX: a **Flat-field correction** section in the existing scrolling Roll panel **before Calibration**, with Choose reference RAW, filename, Enabled, Edit area and Clear. Edit area uses the viewer for automatic rectangle inspection/manual edge adjustment, accept/cancel, then returns to the working photo. New references do not automatically enter the filmstrip. **Do not hide/remove an existing filmstrip photo used as a reference**; hiding/role badges are out of scope. No extra toolbar/viewer panel. Enabled is persistent processing state, distinct from transient source inspection.

### Verified estimator checkpoint

`src/flat_field.rs` provides a scalar RGB gain field, maximum 256×256 nodes. It rejects malformed geometry/nonfinite or nonpositive reference data, ill-conditioned fits and unrepresentable gains. Local trend-based defect rejection precedes separable quadratic Gaussian regression in log camera RGB (sigma 6 grid cells). Regression avoids the slope/curvature bias of simply truncating a blur at rectangle borders; no samples outside support enter the fit. A synthetic failure in the initial median-based rejection exposed false dust detection on steep corner slopes; subtracting the local trend fixed it without weakening the assertion.

The neutral AP0 target is `[Y,Y,Y]` using measured centre-patch luminance; inverse camera matrix supplies the camera-RGB target. Gain-grid normalization uses the actual source-coordinate bilinear evaluator at image centre. Nodes include rectangle edges; outside support, the foundation explicitly returns identity (no implicit crop or unbounded field extrapolation). Source storage remains untouched; gains are applied only by callers once integration is completed.

Local fitting outperformed global degree-2/4/6 polynomial models. Independent **187 full-resolution 64×64 patches per RAW**, including support boundaries, give neutral RGB RMS **0.00138 / 0.00156 EV** (about 0.10 / 0.11%), max **0.00466 / 0.00807 EV**. The independently measured centre-patch luminance changes **−0.00077 / −0.00089 EV**. Localized dark reference defects remain instead of being reproduced as correction spikes. A field holds **40,986 RGB gain nodes / 983,664 bytes** for these references; the maximum scalar field is 1.5 MiB. [Compact evidence/reproduction](../../research/evidence/flat-field-initial.txt).
