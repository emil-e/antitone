# Architecture overview

This describes the implemented application, not the delivery plan. Current work/order lives in [PLAN.md](../PLAN.md); detailed invariants and rationale are indexed in [the documentation map](README.md).

## System boundaries

Antitone is a single Rust package with narrow native bridges. The numerical core can be tested without the desktop stack. Cargo features add `project`, `raw`, `gpu`, `render`, `export`, `ui` and `editor`; `editor` assembles the desktop application. Versions are pinned in `Cargo.toml`/`Cargo.lock`; `rust-toolchain.toml` selects the shared developer toolchain. Developer builds use ordinary Cargo with the aliases/compiler configuration and pinned native setup described in [the README](../README.md).

| Boundary | Implementation | Responsibility |
| --- | --- | --- |
| Scalar processing | `src/{processing,color,sampling}.rs` | f64 reference, response/domain validation, colour transforms, compensated means, actual-response neutral fitting |
| RAW development | `src/raw.rs`, `native/raw_bridge.{h,cpp}` | Owned LibRaw handle, controlled development, metadata/matrix and sensor diagnostics |
| Full-resolution source | `src/scan.rs` | Cached developed source, calibrated sampling, RGB16 preview/tile extraction |
| GPU processing | `src/gpu.rs`, `src/shaders/{camera_conversion,film_response,processing}.wgsl` | Exact integer source representation, accurate temporary conversion/response, AP1 results and floor flags |
| Output rendering | `src/rendering.rs`, `native/{ocio_bridge.cpp,rendering_transform.h}`, `assets/ocio/` | Shared OCIO ACES target definitions, CPU reference/export and pinned generated GPU algorithms/tables |
| Geometry | `src/{geometry,crop,coverage,frame_raster}.rs` | Source/oriented/frame/raster types, source-anchored basis/pivot, exact pixel-cell coverage, nearest-centre sampling, composition and affine adapters |
| Viewer/refinement | `src/{renderer,viewer,refinement,resample,viewport}.rs` | Shared immutable GPU resources, provisional images, bounded tiled settled rendering/rectangular or affine footprint averaging and transient frame/canvas layout |
| Image scopes | `src/{scopes,gpu_scopes,editor_scopes}.rs`, `src/shaders/{scopes,scope_display}.wgsl` | Target-native waveform/vector bins, accepted-frame proxy sampling, bounded scheduling and transient controls |
| Desktop host | `src/platform/{host,macos}.rs` | winit events, egui integration, owned wgpu surface, native SDR tagging, repaint/surface lifecycle |
| Editor | `src/{editor,editor_controls,editor_crop,editor_navigation,editor_document,editor_files,editor_flat_field}.rs` | Stable-ID document state, live edits, crop/picker/reference workflows, file menus, staged worker transitions and GPU preflight |
| Output files | `src/{export,profiles}.rs` | Full-source TIFF/AP0 EXR, encoding/ICC/metadata, bounded buffers and safe destination replacement |
| Project state | `src/project.rs` | Schema-4 camera-model documents, stable source IDs/order, identity/compatibility and atomic save/load; relink primitives have no editor UI yet |

There is no eframe host, vendored renderer patch, custom demosaicer or CPU interactive-viewer fallback.

**Roll-level flat-field correction:** `src/flat_field.rs` estimates/evaluates a bounded three-channel camera-RGB gain field with robust local log-light regression and centre luminance normalization. `Scan::estimate_flat_field` collects weighted full-pixel reference statistics within accepted support; optional `Scan::set_flat_field` applies gains in camera coordinates before CPU measurements/inversion/fitting. Its neutral/centre-luminance target uses camera→AP1→XYZ without assuming equal camera channels. `processing_calibration` propagates the existing one-code bound without modifying stored Dmin/Dmax. `gpu_flat_field.rs` owns immutable shared gain storage; `SourceGeometry` uses canonical `SourceRaster` for sparse-preview/full-tile pixel centres, retaining GPU range checks and the equivalent shader adapter. `GpuImage::set_flat_field` binds it and invalidates cached parameters; refinement accepts the same resource and rejects CPU/GPU map mismatches. Source storage remains RGB16. `editor_flat_field` owns transactional reference preview/rectangle acceptance and one shared roll CPU/GPU map; accepted correction reaches provisional/settled views, full-resolution picks/fitting, thumbnails and exports. `project_flat_field` persists the map, algorithm contract, enabled state, reference identity and source/roll development snapshots including fixed WB. Reference-only records do not enter the filmstrip; existing photos stay visible. [Plan/checkpoints](plans/completed/flat-field-correction.md#verified-editor-checkpoint).

## Data and colour flow

```text
RAW Bayer samples
  → LibRaw black subtraction / fixed roll WB / AHD development
  → developed camera RGB16 (four u16 slots; fourth ignored)
  → normalize / optional source-coordinate camera-RGB flat-field gains
  → native-camera RGB calibration / model-4 inversion / roll gamma balance
  → positive camera-to-AP1/D60 matrix / exposure / photographic Bradford WB
  → signed/HDR AP1 working RGB
       ├→ AP1-to-AP0 → scene-linear EXR (no DRT/monitor conversion)
       └→ pinned OCIO ACES 2, 100-nit sRGB or P3/D65
            ├→ target transfer / quantization / ICC → RGB16 TIFF
            ├→ native-target transfer → approximate accepted-frame scopes
            └→ target-to-extended-sRGB / encoding → tagged SDR layer
                 → OS monitor conversion
```

Calibration and fitting operate on full-resolution source pixels, never display pixels. Dmin/Dmax are each one native-camera RGB value; they carry no source/rectangle relationship. The development matrix is derived from the camera-to-sRGB convention with explicit XYZ/Bradford D65→D60 conversion. A retained roll camera-model/matrix identity rejects mismatched native-channel sources/references; it survives source removal. Base floor is exactly one native code, with the same corrected bound used directly by CPU/GPU/persistence paths. Source bypass enters the rendering path as developed AP1 while ignoring inversion/photographic edits; its transient inspection EV scales only the source-preview post matrix before unchanged ACES. It does not change development, measurement/fitting, saved grades or exported processing.

All response shapes use camera processing model 4 with precise temporary arithmetic. `Response::Original` / numerical defaults denote the classic toe-1/shoulder-0 curve, not an AP0 compatibility branch. New grades use toe 2.5/shoulder off. Camera→AP1 occurs after response; roll-neutral fitting targets the camera direction mapping to AP1 white. Old AP0 schemas/models reject explicitly. See [processing contract](contracts/processing-model.md).

ACES's specified rendering limits are downstream of signed working data. Neither display limiting nor the TIFF transfer affects AP0 EXR. Generated shader assets are algorithms plus small parameter tables, not a baked 3D LUT.

## Ownership and execution

- `RawFile` uniquely owns the native LibRaw handle. `Developed` borrows its camera image; a mutable development operation invalidates the previous view. `Scan` retains the selected developed source and reads it without redecode on adjustment or picking.
- The winit/egui UI owns live edit/view state. A single backend thread owns the selected `Scan` and serially handles load, document work, full-resolution pick, export and refinement commands over channels. Reference editing temporarily owns an additional uncorrected `Scan`, retaining the working photo until accept/cancel; acceptance prepares the corrected candidate before replacement. Imports register headers/fingerprints without developing the whole roll. The first successful development fixes a new document's WB; every later load uses explicit document WB, including reopened projects. Candidate documents/initial GPU previews are prepared before replacing the active scan/state.
- UI, backend and thumbnails share the same wgpu device/queue and one lazily initialized `GpuRenderer`. Initialization is prewarmed in parallel with import/development; errors remain reportable through the shared factory. Processing, both target ACES pipelines/tables, presentation and rectangular/affine averaging pipelines are immutable shared resources. Source/working/output storage, source/correction revision and preparation signatures remain image/job-owned. Viewer and scope callbacks share whole-proxy processing/ACES preparation; backend refinement uses independent tile/output images. Scope bins, reduction/readback identity and invalidation remain owned by the editor's `GpuScopes`, not the shared renderer or thumbnail cache. Results return as `Arc<GpuImage>` or small measurements/outcomes. Header verification hands the same owned RAW handle into development, rather than opening it again. Source-built OpenMP/LibRaw target macOS 14 in private `.cache/native-deps`; per-call task ICV scopes bound foreground/background threads and put idle workers to sleep. `RawFile` tracks decoding separately from optional full diagnostics; regional picks read original sensor data after processing without a whole-sensor scan. [Native decision](decisions/parallel-libraw.md).
- Request IDs and generation counters reject stale source/refinement results. Refinement checks cancellation between tiles; submitted GPU dispatches themselves are not cancellable. Picks/exports run against the requested loaded source and a settings snapshot; app-level export cancellation is not implemented.
- Proposed edits/picks are validated before state mutation, including calibrated inversion and GPU precision/range. Worker failure or invalid input is reported; no silent numerical/rendering fallback is selected.
- `CpuRenderer` RAII-owns an OCIO processor behind an exception-translating C ABI. CPU rendering is for export/reference, not interactive presentation.

## Preview, resources and caches

The responsive provisional preview uses nearest-centre camera RGB16 samples on a bounded grid. Processing/rendering after sparse sampling is approximate; measurements and exports never consume this proxy.

After 250 ms idle, refinement visits the bounded source region needed by the **visible composed frame**, processes/renders it in `1024×256` tiles, then area-averages **linear rendered target RGB** to the physical display grid. Exact geometry retains rectangular source-space averaging; each tile dispatches only its overlapping output rectangle, with a conservative boundary pixel for f32 arithmetic and unchanged fractional weights/order. Rotated framing retains full-output dispatch and reconstructs each inverse-mapped destination box with exact source-cell intersection weights; rectangular overlap bounds are not applied to affine footprints. Bounding-box-only pixels are not included in the average. Nonlinear inversion does not commute with averaging negative inputs. Regional refinement is not a scope input; scopes independently sample the whole accepted composition from the existing whole-source proxy.

Each source pixel occupies 8 bytes. A tile source buffer is 2 MiB and the existing working buffer 4 MiB. Camera constants occupy 144 bytes; processing parameters/signatures 224 bytes. Higher precision is temporary expansion/pair arithmetic, not a retained wide source image. `GpuImage::new_rendered` creates a settled target/presentation image without source, working or unused processing resources.

The host requests the adapter's reported storage-binding and buffer-size limits; other device limits remain at wgpu defaults. These are API capacities, not reserved memory or an aggregate application budget. Averaging retains 16 scratch bytes per output pixel alongside the 16-byte linear output texture. Strip reconstruction is deferred unless actual memory/performance problems justify it.

`GpuImage::prepare` is keyed by actual parameters and shared by viewer/scope callbacks; either can prepare first, and unchanged repaints do not rerun compute/render work. Source/correction replacement increments image revision and invalidates that key; rejected source writes do neither. Renderer reuse never substitutes for scope image/revision identity. Cropped presentation bindings also reuse unchanged affine mappings. The editor keys settled work by target/view and rejects old generations. Only one settled job/tile is outstanding; waits target that tile's submission rather than later UI submissions. A measured 1/2/3-depth experiment retained depth 1 because the throughput gain worsened foreground latency. Scope reduction/readback retains its separate one-outstanding bound; thumbnail phase cancellation cannot invalidate scope bins or selected processing. An aggregate application memory budget and whole-roll RAW cache are not implemented. [Performance closure and integration boundaries](plans/completed/rendering-performance.md).

`editor_thumbnails` uses a separate one-request worker, leaving the selected `Scan` untouched. A verified selected Scan seeds its exact maximum-dimension-256 uncorrected RGB16 proxy; transient references cannot seed the working photo's identity. Cold requests verify full RAW bytes, reuse a versioned/checksummed disk proxy when available, or develop one temporary RAW with recorded WB and verify it again before proxy extraction. RAW/header/development mismatches are errors; corrupt/unavailable disposable cache entries are diagnostic misses. Resolved locators are used for both fingerprint checks.

Worker RGB16 and UI GPU LRU caches use machine-capacity byte budgets and OS pressure states rather than 16-entry limits. Visible GPU entries and the current selected proxy are protected working sets; optional recent entries evict first. Empty/failed replacement views release the source protection. Inactive correction generations leave the GPU cache, so it cannot retain old gain maps. Source ID/fingerprint/source and roll development key in-memory proxies; target and exact active correction additionally key GPU images. Disk identity excludes locator/document ID/grade/target/correction; disk retention is bounded to 128 MiB at `~/.cache/antitone/thumbnails-v1`. Policy details and exclusions live in [the output contract](contracts/output.md#responsiveness-and-optional-caches).

Actual grade/view changes reuse source work; accepted parameters rerun GPU processing only when changed. Uncalibrated thumbnails show zero-gain source. Visible requests precede nearby and then farther unshown photos during foreground/refinement idle. Optional idle prefetch requires spare GPU budget, never evicts retained work to make room and uses no-touch cache membership checks; renewed foreground or missing-visible work cancels offscreen prefetch. Scroll/document/foreground transitions cancel obsolete phases; stale results never install and one outstanding request prevents a backlog. Warning pressure disables prefetch; critical pressure cancels/suspends new thumbnail work and removes optional entries. A pressure observer wakes the UI only on transitions, not perpetual idle repaint. Horizontal virtualization and resize remain transient; no project schema/export change.

**Responsive scopes:** `Editor::scope_input` selects only calibrated positive whole-source images and declares a whole accepted-composition `FrameRaster` at the proxy's sampling pitch. Reduction uses canonical `Composition::texture_mapping` at frame sample centres, after native-camera processing/ACES and before target-to-monitor conversion. Waveform x follows final-frame order; crop source bounds and regional settled views are never substitutes. This is nearest-proxy approximation, not full-source export reconstruction. Source/reference/busy views and crop drafts suspend scopes. One reduction/16-byte asynchronous diagnostic readback is outstanding; geometry joins image/revision/parameters/target/projection/scale identity. Compatible grading bins remain labelled Updating, but composition/source/basis changes cannot paint old bins. RGB/luma reuse four planes. Bins/totals retain 1,049,616 bytes plus small uniforms/bindings/readback and unmeasured driver overhead, with no extra RAW/wide retained image. Scope sizing/mode/scale are transient; the slot above tabs reserves pinned geometry/Output controls and never changes viewer dimensions. [Scope contract](contracts/scopes.md), [closure/limits](plans/completed/vectorscope-and-waveform.md).

## Spatial geometry

`geometry` owns the [coordinate contract](contracts/geometry.md), separate from colour transforms and egui. `raw::Rect` aliases its source-region type; `Scan` proxies and project region validation use shared mappings. Composition is active source → shared roll quarter-turn → roll displayed-axis flips → photo quarter-turn → photo displayed-axis flips. Persistent roll/source orientation and source-centred framing are independent of colour grading. A source-plane basis angle about the crop centre defines actual coverage; composition transforms this frame/basis through exact orientation, preserving included source content under turns/flips. Integer frame extents define output dimensions; source bounding regions limit iteration only. Source/camera development and flat-field coordinates are not reoriented.

`viewport::CanvasLayout` maps the composition to logical UI points. `Viewport::layout_crop` Fits the projected full active source once and retains an unclamped editing anchor/physical scale; draft resizing reanchors from the painted layout rather than refitting the crop. Below the Roll/Photo tabs, the selected scope's pinned panel shows shared Scan orientation on Roll or per-photo Composition (orientation actions and transient crop controls) on Photo, never both. Switching tabs only hides/reveals controls; it does not cancel crop drafts or change the viewport/pipeline. Flip buttons toggle the same durable orientation fields without exposing canonical flags as checked states. Crop drafts and bracket/thirds overlays remain transient UI only. Navigation centre is explicitly in frame coordinates; picking stores inverse-mapped source coverage of canvas-aligned frame rectangles, with drag clamping/UI boundary snapping separate from mapping. Exact selections retain original rectangular sampling; rotated selections use compensated area-weighted full-resolution RGB/fitting and matching positive-coverage sensor-site row spans. Source inspection/picker entry preserves exact orientation and precision navigation. Dmin/Dmax temporarily reveal uncropped oriented source at the same physical magnification/source anchor, then restore the working crop/viewport after picking or temporary reference selection. Fitted views freeze magnification while picker toolbar layout changes canvas size; Gamma/WB retain crop/grade and intentional in-picker navigation.

Provisional textures and exact settled textures remain source-oriented and use shared affine presentation. Rotated settled textures are already in destination-frame order and present directly; their `FrameRaster` and source bounds travel in the request/signature. `AreaAverage` retains its exact rectangular kernel and adds a GPU convex-coverage kernel; neither uses a CPU interactive fallback. Composition joins the settled request signature so old generations cannot install after an orientation/crop change. Crop editing is a transient constrained draft: provisional presentation reveals/dims surrounding source with the same grade, while settled jobs and file/picker/grade actions wait for Apply/Cancel. Thumbnails likewise apply current composition/aspect during paint and retain geometry-independent source/processed caches. Export holds a composition snapshot; exact framing remaps full-resolution pixels, while rotated framing weights individually processed pixels. TIFF filters after ACES in linear target RGB using bounded strips; EXR filters signed/HDR scene-linear data before AP0 serialization. No independent viewer/thumbnail/export orientation equations remain.

## Presentation and exports

The host owns the surface and reapplies explicit extended-sRGB tagging after configuration. It uses `RGBA16Float`, encoded extended-sRGB SDR content and EDR disabled. The image callback converts from the selected linear target and encodes once; ordinary egui UI is already encoded sRGB. Core Animation/ColorSync performs monitor conversion—there is no second DRT or application monitor transform. Software tagging/readback is not physical-monitor validation.

TIFF/EXR are recomputed from full-resolution source through the f64 pipeline. TIFF then uses OCIO CPU rendering, matching transfer/ICC and RGB16 LZW/prediction. EXR converts AP1 to AP0 and writes ZIP16 half/full with overflow rejection. Writers use same-directory temporary files and safe no-overwrite/confirmed replacement; buffers currently have a 1 GiB cap each. These guarantees are not a full power-loss or cross-platform exclusive-rename claim. See [output contract](contracts/output.md).

## Persistence boundary and known gaps

`Document` owns authoritative `Project` state, its path and saved baseline. Accepted controls flush into source-ID-owned photo settings and shared roll/calibration/output state; no competing path-keyed photo store remains. Exact shared/per-source orientation, accepted framing/basis and accepted flat-field support/gains/reference identity/Enabled are durable. Crop drafts/aspect preferences, reference-support drafts, selection, ordinary picker coverage/return context, viewport, source bypass, GPU resources and worker IDs stay transient. Save validates a snapshot and updates the baseline/path only after atomic write success; Save As rebases relative locators. Open verifies runtime/GPU domains and ordered sources, prepares the first photo with saved WB, then commits. New/Open/Close share a Save/Discard/Cancel guard; document work suppresses stale mutations while retaining the old display. See [project-state contract](contracts/project-state.md).

Recovery/autosave, missing-source/relink/changed-source UI and undo/redo remain future work. Unavailable ordered RAWs currently reject Open; nonordered unavailable records and stored reference RGB remain preserved.

Source-inspection brightness and Mac scroll/pinch/click/drag/cursor/Fit behavior are implemented; physical trackpad feel remains unverified. Bounded thumbnails are implemented. Other scheduled gaps include scope photographic acceptance/deferred full-source analysis, remaining layout/colour investigations, dense alignment guides and photographic geometry acceptance, assisted roll analysis, batch/export cancellation/metadata and distribution. See [roadmap](../PLAN.md), not this overview, for priorities. Broader device/resource tests, macOS 14 and physical-monitor checks remain separate acceptance work; no minimum chip/RAM target has been established.
