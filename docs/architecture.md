# Architecture: where the work belongs

Antitone is one Rust package with small native bridges. The numerical core builds without the desktop stack. Cargo features add persistence, RAW development, GPU processing, rendering, export and the editor, so a contributor can work on one boundary without building everything.

For the photographic model, start with [processing](processing.md). This page is a map of the implementation and its ownership, not a second specification of every feature.

## Ownership and execution

The UI owns live document and view state. A backend thread serializes source loading, document preparation, picks, analysis, export and refinement. Mutable `RawFile` development stays worker-local; successful camera development is consumed into private frozen native ownership. A `Scan` leases an immutable `DevelopedSource` holding native RGB16, Sony-corrected f32 or direct-SDK DNG f32 camera samples, original CFA and camera/WB metadata, while keeping its own illumination-correction context. Leases share sample storage without copying RGB, and read-only capture diagnostics never unpack or mutate the SDK after publication. Final native destruction follows the last lease and image borrow, including synchronized transfer to another thread.

The [document-scoped CPU store](../src/source_store.rs) retains immutable native developments and uncorrected proxies in one byte-bounded oldest-unprotected LRU. Active leases survive eviction; closing a store rejects publication without invalidating readers. Selected/visible proxies are protected separately, while native cache ownership is always optional. Charges cover exported explicit native allocations and Rust payload, not allocator/driver footprint; unavailable accounting disables optional admission, not processing. File queries and destruction stay outside metadata locks.

Candidate documents borrow compatible parent leases with zero optional retention and transfer compatible ownership only on acceptance. Thumbnail completion is separate from residency: eager CPU/disk work persists proper proxies without requiring offscreen GPU images, including while fullscreen hides cards.

One [native priority worker](../src/editor_development.rs) serves foreground, visible and eager development, arbitrating between noninterruptible calls. Compatible same-family demands join with per-consumer cancellation/publication rights. Mutable RAW handles remain worker-local; completion hands off frozen sources even at zero optional budget. Paused/in-flight backing is mandatory work, not optional retention. [Scheduling rationale and diagnostics](native-development.md#editor-scheduling) describe the tradeoff; [broader resource acceptance](plans/visual-feedback.md) remains separate.

[Thumbnail CPU/disk/GPU processing](../src/editor_thumbnail_worker.rs) and embedded-camera-preview extraction remain separate background paths, not additional RAW development pools. Native thumbnail tickets are asynchronous: visible misses can enter the native queue while older eager CPU/disk work is still owned. GPU processing remains serial, and obsolete GPU tickets never install images. These paths must not borrow the selected Scan away from foreground operations. Analysis joins/reuses compatible sources or requests temporary native work from the same scheduler, retaining only bounded statistics rather than a roll of mandatory full developments; analysis misses do not independently add optional native ownership. Registered flat references use document-native reuse; external unaccepted references remain uncached. Export uses its existing retained Scan.

UI, backend and image workers share a wgpu device/queue and reusable immutable GPU infrastructure. Mutable processing/storage and signatures remain image/job-owned. One [export engine](../src/gpu_export_area.rs) serves TIFF and EXR: bounded original processing, FP32 linear pixels, stable source-cell area reconstruction and destination-only readback, with one unit outstanding on the calling worker. Only TIFF adds look/ACES/transfer; EXR retains scene-linear signed/HDR AP1 for AP0 serialization. Exact crops and repaired edges use that same engine. Exact whole-frame relevance masks prevent native mapping roundoff from admitting unresolved cells outside the captured frame. The renderer caches one export processing kernel alongside shared ACES/look resources; original and repair-grading pipelines are compiled from that kernel's same operator module. Physical-view and export colour grading reuse common stable operators while retaining distinct sampling adapters. Existing editor background prewarm requests the export kernel, while direct library use is lazy. No export geometry producer or additional GPU/RAW worker is needed. CPU encoders and atomic publication remain shared. CPU photographic processing and OCIO composed exports are independent diagnostic/test references behind `ocio-reference`, not production fallbacks. [Output](colour-and-output.md#tiff-and-exr-serve-different-purposes) owns reconstruction and lifetime details.

The shared processing kernel evaluates inversion directly for integer and continuous camera samples, without an exact-code response cache. Correction, flooring and photographic arithmetic share one original-sample model; source inspection bypasses inversion. Original storage follows source precision: native RGB16 without effective embedded correction, or f32 after Sony shading/reconstruction or SDK DNG development, without redundant native RGB development. DNG uses explicit original/border/processing-limit flags and its own source precision and saved-development identity; it does not inherit Sony lens metadata or LibRaw's WB basis. Physical AP1 support has a separate view-scoped lifetime.

Editor grade routing reuses immutable constants by complete processing content, including roll WB and ordered local values. Metadata/view state does not recreate grades; selected/visible retention bounds editor ownership, while callbacks, image signatures, scopes and the one outstanding refinement can retain older versions. Selected/pending proxies share one immutable camera source across lazy active-target outputs, while filmstrip processing remains independent. Provisional AP1/target storage is released once the working view is accepted and recreated only for a consumer. Mutable outputs are never shared between images. These ownership bounds do not establish an aggregate device-memory budget.

The working-view owner separates asynchronous linear-source acquisition from frame-bound processing for both positive grading and ordinary source inspection. Their acquisition identities differ: the positive caches neutral inversion, while inspection caches corrected camera-to-AP1 light and applies only source-preview gain downstream. It owns normal demand revisions, accepted presentation and background-idle readiness; original comparison/tool reconstruction has a separate purpose-bound owner rather than a competing normal-view lifecycle. Its latest-request mailbox runs on that same backend and borrows the authoritative developed source; it introduces no RAW loader, cache or worker. A physical-view AP1 source is reused across Global edits; immutable graded AP1 and target-linear results are shared by viewer/scopes. One submitted colour version coalesces newer controls until completion. Navigation reacquires originals, with bounded original and destination work. The first traversal also acquires coarse whole-composition neutral AP1; matching immutable grade/target parents compose missing coverage into one viewer/scope result without replacing available detail. Both colour and navigation-composition submissions coalesce instead of accumulating display-sized versions. Explicit original comparison requests original-sample processing; normal viewing never schedules hidden idle reconstruction. Completed references may retain existing image-cache allowance after comparison ends, without silently replacing working detail. [The editor guide](editor.md#a-stable-working-view-while-grading) owns lifecycle, bypasses and remaining aggregate-memory/photographic acceptance.

Project sources own accepted Dust instructions; the controller owns source-keyed selection, gesture drafts and asynchronous evaluations, independently of view generations. Edits update the source record directly, without a second writable repair collection. The existing backend owns evaluation and bounded reconstruction. GPU donor screening uses job-local buffers and the shared submission gate; the CPU scores donors, chooses the winner and computes healed values. The reusable screening pipeline outlives those buffers, and completion waits occur outside the gate. Source epochs and request identities govern cancellation and publication.

The accepted image recipe supplies the same repair intent to viewer, reference, scopes, export and proper thumbnails. Consumers own resolution, execution and readiness; they can evaluate offscreen without Editor or viewer warmth. Immutable sparse results and GPU snapshots may outlive current requests while submitted consumers retain them. [Processing](processing.md#one-accepted-image-recipe) owns recipe/stage semantics, [projects](projects.md#source-owned-dust-repairs) owns saved instructions, [output](colour-and-output.md#tiff-and-exr-serve-different-purposes) owns export reconstruction and failure safety, and [editor](editor.md#provisional-dust-cleanup) owns interactive evaluation, repaired views and thumbnail retention.

Surface reconfiguration must not overlap submission on the shared queue. The host and background submitters use the same [submission gate](../src/gpu_submission.rs), excluding new submissions while wgpu drains GPU work for a resize. CPU tile preparation, command encoding, staged uploads and explicit completion polls remain outside that gate. Opt-in hosted latency tracing attaches a frame's completion callback under the gate, before a background submission can advance the observed queue fence; it does not change processing or establish physical presentation timing.

Creative-look resolution is downstream of source/photographic state. Built-in model generation and imported-file validation converge on one immutable numeric asset; only that asset reaches shared positive rendering and saved projects. The resolver's persistent derived cache is disposable, while saved embedded samples preserve appearance independently of generators. Numeric LUT identity participates in rendered signatures but not neutral-source or graded-AP1 reuse. Live bindings retain GPU samples weakly deduplicated by the renderer; image budgets conservatively count actual look allocations, not hypothetical capacity for None. Asynchronous validation readbacks keep the host polling until their callbacks complete, including when no new frame is requested. [Colour/output](colour-and-output.md#creative-looks-precede-output-rendering) and [project storage](projects.md#embed-the-accepted-look-not-a-catalog-reference) own the guarantees.

Worker results are proposals. Request IDs, generations and source/settings snapshots determine whether they still belong to the current operation. Prepare and validate before replacing accepted state; discard stale results. Cancellation is cooperative, not a promise to interrupt LibRaw or already-submitted GPU work immediately.

## Editor workspace

[Application menus](editor.md#application-menus-and-settings) share a portable action/grouping model between AppKit and egui presentation. The editor owns availability, focused-text routing and guarded dispatch; the host owns native lifetime and event-loop wakeup. File actions render outgoing controls after surrendering focus before snapshotting accepted state. Settings/About/Help panels block workspace input without acquiring document or processing ownership. [Native termination](editor.md#native-quit-negotiation) negotiates the editor's live close/save continuation with AppKit, preserving winit's delegate and completing cleanup before an affirmative reply can exit the process. The native menu backend uses `muda`; native file panels temporarily restore responder-based Edit commands for their own text controls.

[Shared presentation](editor.md#build-ui-from-shared-presentation) lays out supplied state and returns responses, and owns the editor's [colour](editor.md#colour-roles) and [typography](editor.md#typography-roles) roles. Photographic adapters own value semantics; feature controllers own state, availability and dispatch. This keeps a presentation change from acquiring processing or persistence responsibility. [Decision dialogs](../src/editor_ui_dialogs.rs) own framing, button focus and dismissal; document and export controllers retain the decision payloads and transaction dispatch. Analyze retains its reset consequence within the sampling-area review, using shared warning presentation rather than another decision dialog. [Feedback presentation](../src/editor_ui_feedback.rs) shares that shell and supplies severity/details; [operation feedback](../src/editor_feedback.rs) owns failure copy, acknowledgement and resolution without acquiring worker or persistence responsibility.

[Task activity](../src/editor_activity.rs) owns one private foreground presentation lifecycle: typed requests, progress/cancellation state and feedback presentation, including Analyze. [Working presentation](../src/editor_ui_progress.rs) renders its supplied views. Feature controllers retain pending snapshots, worker protocols, cancellation signals and atomic promotion; task completion changes presentation only.

[Analyze review](../src/editor_analysis_review.rs) owns temporary per-photo support and a separate browsing return context. Bounded camera-code captures feed pooled conservative holder support and independent per-photo picture evidence; normal fine-measurement interiors strengthen one shared opening before review. Region inference explicitly rounds continuous camera samples to RGB16 evidence, without changing photographic samples. Preparation can preserve exact fine RGB16 inference rasters in a bounded anonymous temporary file while the roll model is fitted, rather than developing those RAWs again. This scratch belongs only to that request and closes on success, cancellation or failure; it neither retains native sources nor enters project persistence. Capacity or scratch-I/O failures use the original validated reacquisition path, never different measurement values or omitted photos. File revisions are checked again before consuming scratch. Only small geometry/provenance and frame evidence persist, not the inference rasters. Original full-resolution samples and existing numerical gates remain with analysis. Accepted support and grading promote together, never a review draft on its own.

[Photo-only inspection](../src/editor_fullscreen.rs) retains the temporary workspace/view context and suspends tools without promoting drafts. The host owns window geometry and menu/Dock presentation, independent of native fullscreen Spaces, and acknowledges restoration before the controller restores its snapshot on the next UI frame. [Shared viewer framing](../src/editor_ui_viewer.rs) owns docked/auto-hiding controls and the full-canvas surface; it does not own image mappings, transactions or window state.

[Roll selection](../src/editor_roll_selection.rs) owns transient membership/anchor state and confirmed project-only removal. Filmstrip cards present supplied selected/active state; temporary picker browsing retains the working selection. Empty-roll removal invalidates image work and releases the backend Scan without resetting the retained processing basis.

[Auto-crop](../src/editor_auto_crop.rs) consumes compact source-owned frame measurements independently of Analyze's sampling policy. Auto-crop requires already-retained accepted evidence; [feature-neutral lazy preparation](plans/region-detection.md#next-actions) remains unfinished. For roll/selection operations, a controller-owned draft captures successful source identities, original proposals and freshness snapshots. Single-photo Auto-crop instead initializes the existing manual Crop draft through the same proposal/eligibility adapter, without another session or accepted-state mutation. Margin edits change only those previews. Skipped-source reasons remain attached to that transient tool result, including when no source can be proposed, so shared thumbnail/tool warning artwork can explain absent outlines without redoing detection. Apply validates every target before installing crop/angle atomically; Cancel drops the draft, leaving accepted state intact. Uncertain sources and all grading/support remain unchanged. Representative inspection uses the existing working/original service on the uncropped oriented scan with shared crop artwork; margin drags do not reacquire that background. Filmstrip framing uses an explicit transient override, never temporary project mutation. Only applied crops persist/export through existing composition owners. The shared shelf/inspector/viewer group presents the mode; it owns no transaction machinery or new image pipeline.

Accepted photographic state lives in [projects](projects.md). Tool drafts and viewport state are transient; durable UI preferences, including fixed CPU/GPU cache limits, are stored independently. Defaults use installed RAM and static GPU facts only at initialization/reset; pressure changes effective optional retention, not saved limits. [Editor](editor.md) explains preview/cache distinctions and the input/transaction model.

## UI test boundary

The opt-in `ui-tests` feature keeps egui_kittest cases in the Editor's private [test module](../src/editor_kittest.rs). The harness invokes production `host::App::ui` offscreen without exposing editor state publicly. Its RGBA16Float renderer shares the real device/queue and submission gate and executes production paint callbacks.

The separate [native-host executable](../tests/native_host.rs) runs the production host on the main thread and launches a window only with explicit `--run`. Its authored Editor case uses the public constructor and observes actual canvas/surface painting. [Development checks](development.md#framework-ui-regressions) explain fixtures and commands; [native-host limits](development.md#explicit-native-host-checks) distinguish that basic composition coverage from physical input and broader appearance acceptance.
